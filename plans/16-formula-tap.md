# Plan 16: Formula and tap CI

Part of the Claude Desktop Resource Monitor v3 build. Full requirements: [`../requirements/REQUIREMENTS-v3.md`](../requirements/REQUIREMENTS-v3.md) (incremental on v1 and v2). Execution order and rationale: [`index.md`](index.md).

## Context

With `v0.3.0` tagged (Plan 15), this plan writes the Homebrew formula and the tap's CI in a second repository, `thamwangjun/homebrew-tap`, cloned locally at `../homebrew-tap`. It ends with a formula PR whose CI builds the arm64 macOS 26 bottle. Publishing that bottle is Plan 17.

Facts this plan relies on (REQUIREMENTS-v3 §3):

- Homebrew builds Python formulae from source: pip gets `--no-binary=:all:`, and `virtualenv_install_with_resources` uses build isolation, so each package's build backend is also built from source. PyPI releases newer than Homebrew's cooldown are refused.
- `uv_build` built from source needs Rust (its sdist uses `maturin`). Homebrew's build environment does not see mise tools, so the formula needs `depends_on "rust" => :build`. `:build` dependencies are skipped when a bottle is poured.
- `brew tap-new` generates template files, including GitHub Actions workflows (with `--no-git`, no git repository). It creates the tap inside Homebrew's own directory (`$(brew --repository)/Library/Taps/<user>/homebrew-<repo>`), not in `../homebrew-tap`.
- Homebrew developer commands (`tap-new`, `style`, `audit`, `update-python-resources`, `test-bot`) switch **developer mode** on (`brew update` then follows `main` instead of stable tags). Observed 2026-09-27. This plan switches it off again at the end.
- Homebrew `rust` is not installed on the reference machine (`brew list --versions rust` empty, 2026-09-27). It must stay that way (B-3, V-17).

## Goal

`../homebrew-tap` holds CI workflows and `Formula/claude-desktop-monitor.rb`; every package builds from source with mise's Rust (V-19); `brew style` and `brew audit` pass; the user's formula PR has green CI that built the bottle.

## Design

### Formula (`Formula/claude-desktop-monitor.rb`)

```ruby
class ClaudeDesktopMonitor < Formula
  include Language::Python::Virtualenv

  desc "Watch Claude Desktop's resource usage over time in a terminal UI"
  homepage "https://github.com/thamwangjun/claude-desktop-monitor"
  url "https://github.com/thamwangjun/claude-desktop-monitor/archive/refs/tags/v0.3.0.tar.gz"
  sha256 "<from plan 15 status>"
  license "GPL-3.0-only"

  depends_on "rust" => :build
  depends_on :macos
  depends_on "python@3.14"
  depends_on "terminal-notifier"

  # resource blocks: generated by `brew update-python-resources`

  def install
    virtualenv_install_with_resources
    # B-5: pync must find Homebrew's arm64 terminal-notifier whatever the user's PATH is.
    (bin/"claude-desktop-monitor").unlink
    (bin/"claude-desktop-monitor").write_env_script libexec/"bin/claude-desktop-monitor",
      PATH: "#{Formula["terminal-notifier"].opt_bin}:$PATH"
  end

  test do
    assert_match "usage:", shell_output("#{bin}/claude-desktop-monitor --help")
    system libexec/"bin/python", "-c", "import claude_desktop_monitor.monitor"
  end
end
```

`brew style` decides the final ordering and wording (for example of `desc`); follow it.

### Resources (B-4)

Runtime dependencies and their transitive dependencies, as in `uv.lock`: psutil, rich, markdown-it-py, mdurl, pygments, watchdog, pync, python-dateutil, six. Generated with `brew update-python-resources` (sdist URLs and checksums, cooldown respected). If it can't resolve a non-PyPI main package from the tag URL, **stop and ask**; don't hand-write checksums without the user's agreement.

### Working with two copies of the tap

`brew` commands need the formula in a tapped repository. The **dev tap** is `../homebrew-tap` tapped by path (`brew tap thamwangjun/tap ../homebrew-tap`), which clones it into Homebrew's directory. After each commit in `../homebrew-tap`, refresh it with `git -C "$(brew --repository thamwangjun/tap)" pull`. Plan 17 replaces the dev tap with the GitHub one.

### CI (B-6)

The workflows from `brew tap-new`, with the test matrix reduced to `macos-26` (arm64). Everything else is left as generated. Whatever the generated workflows need from the repository settings (for example, Actions write permissions to upload bottles and commit the `bottle do` block) is listed for the user, who changes the settings.

## Tasks

1. **Rust pin**: `mise.toml` gains `rust = "1.98.1"`; `mise install`; `mise exec -- rustc --version` shows 1.98.1. Confirm `brew list --versions rust` is still empty.
2. **Clone**: `git clone https://github.com/thamwangjun/homebrew-tap ../homebrew-tap` (empty repository).
3. **Templates**: `brew tap-new --no-git thamwangjun/cdm-scratch`; copy its `.github/workflows/` and `README.md` into `../homebrew-tap`; edit the matrix to `macos-26` and the README's tap name; `brew untap thamwangjun/cdm-scratch`. Show the user the workflows' triggers and required permissions.
4. **Commit templates** on `main` in `../homebrew-tap`: `workflows: add brew tap-new CI` (B-9 attribution lines).
5. **Formula**: on branch `claude-desktop-monitor-0.3.0`, write the formula without resources; commit `claude-desktop-monitor 0.3.0 (new formula)`; tap by path (dev tap); run `brew update-python-resources --print-only thamwangjun/tap/claude-desktop-monitor`; add the blocks in `../homebrew-tap`; amend the commit; refresh the dev tap.
6. **V-19** (mise's Rust; takes several minutes because `uv_build` and `maturin` compile):

   ```
   rm -rf /tmp/cdm-v19
   mise exec -- python -m venv /tmp/cdm-v19
   mise exec -- /tmp/cdm-v19/bin/pip install --no-binary :all: --no-deps --no-cache-dir <each resource sdist URL from the formula>
   uv build --sdist --out-dir /tmp/cdm-v19-dist
   mise exec -- /tmp/cdm-v19/bin/pip install --no-binary :all: --no-deps --no-cache-dir /tmp/cdm-v19-dist/claude_desktop_monitor-0.3.0.tar.gz
   /tmp/cdm-v19/bin/claude-desktop-monitor --help
   /tmp/cdm-v19/bin/python -c "import claude_desktop_monitor.monitor"
   ```

   Build isolation stays on (as in Homebrew), so pip builds `uv_build` via `maturin` from source in the isolated build environment, using `cargo` from mise. Confirm from pip's output that `uv_build` was built, not downloaded as a wheel. `brew list --versions rust` must still be empty.
7. **Lint**: `brew style thamwangjun/tap`; `brew audit --strict --online thamwangjun/tap/claude-desktop-monitor`. Fix and amend until clean. No local `brew install` (it would install Homebrew's Rust; B-3).
8. **User gate**: ask the user to set the repository settings from task 3, push `main`, push the formula branch and open a PR. Then watch the checks read-only (`gh pr checks`, `gh run watch`). On failure: fix in `../homebrew-tap`, the user pushes again.
9. **Clean up**: `brew developer off` and confirm with `brew developer`. The dev tap stays until Plan 17.
10. **Source repository**: README developer-setup Rust note (W-1), `CLAUDE.md`/`PLAN_EXEC_INSTRUCTIONS.md` (Rust pin, `../homebrew-tap`, developer mode), status with the tap commit hashes and PR number. Commit `plan 16: …`.

## Plan-level decisions (not specified in REQUIREMENTS-v3)

- Templates come from a scratch tap (`thamwangjun/cdm-scratch`, `--no-git`), removed afterwards, so the real tap name is never created inside Homebrew by `tap-new`.
- The workflows are committed to `main` first; the formula arrives through a PR from branch `claude-desktop-monitor-0.3.0`, as B-8 requires for bottles.
- The dev tap is the local clone tapped by path; Plan 17 swaps it for the GitHub tap.
- `desc` wording as drafted, adjusted to whatever `brew style`/`audit` require.
- V-19 installs the exact resource versions pinned in the formula, not `uv.lock`'s, because the formula is what Homebrew builds.
